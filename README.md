# 創點子 IdeaX (Platform Architecture & Development Guidelines)

> **核心準則提醒 (Crucial Development Protocol)**：
> **每當平台有任何新功能迭代、按鈕佈局調整、商業邏輯變更、收費規則調整、安全機制更新或測試守則補充時，必須主動同步更新 `src/data/platformManual/` 中的對應手冊檔案！**

---

## 📁 平台內部清單 (Platform Internal Directory) 模組索引

所有管理員內部清單檔案集中管理於 `src/data/platformManual/`，並透過 `AdminPlatformManualCard.tsx` 提供管理員專屬的在線查閱、檔案上傳、檔案刪除與一鍵打包 ZIP 下載功能。

### 模組與檔案對應：
0. **`00_version_info` / `versionHistory.ts` (【版本資訊】與維護規則)**
   - 記錄全站版本號、發布日期、單日 0.2.0 增量規範與版本更新歷程 (Changelog)。
1. **`01_operationsGuide.ts` (01. 系統操作手冊)**
   - 訪客、提問者、解題專家與管理員的完整操作流程與 SOP。
2. **`02_featuresSpec.ts` (02. 核心功能規格清單)**
   - 問題市場、懸賞託管、即時私訊、痛點解鎖、專家認證等功能技術規格。
3. **`03_rulesAndLogic.ts` (03. 平台運作規則與商業邏輯)**
   - 抽成費率、退款與仲裁流程、信譽評分機制與階層權限設定。
4. **`04_architectureAndSecurity.ts` (04. 技術架構與安全機制)**
   - 前端 React/TypeScript 架構、Firebase 規則、身分驗證與資安邊界。
5. **`05_adminMaintenance.ts` (05. 管理員運維應變守則)**
   - 伺服器巡檢、資料庫備份、假資料清理與緊急事件應變措施。
6. **`fileStorage.ts` (檔案儲存與自訂上傳管理)**
   - 管理員自訂檔案的上傳、LocalStorage 持久化、單檔/批次刪除與預設恢復。

## 🏷️ 版本號維護與自動謄寫規則 (Versioning Governance)
工程師在每次功能更動或版本發布時，**必須自動嚴格遵守並自動謄寫以下規範**：
1. **版本序號與結尾字母獨立記數 (Sequence Numbering)**：
   - 每一版皆具備全局連續遞增之「版本序號」（格式如 `#001`、`#002`、`#003`...）。
   - 若單日達上限而產生結尾字母版號（如 `v1.7.2a`、`v1.7.2b`），此類結尾字母版本亦**「單獨佔有一個版本序號獨立計數」**（例如 `#021` 為 `v1.7.2`、`#022` 為 `v1.7.2a`），並同時單獨標註字母擴充記數（例如 `a` 為擴充 #1、`b` 為擴充 #2），確保每一版本皆有獨一無二的專屬序號。
2. **單日增量上限 (+0.2.0)**：
   - 同一日曆天內常態更新，版本號 Minor 遞增上限嚴格限制為 `+0.2.0`（例如基準為 `1.5.2`，當日最多累加至 `1.7.2`）。
3. **達上限後字母後綴擴充**：
   - 若單日已達 `0.2.0` 增量上限，當日後續更新必須自動在版本號尾端附加小寫字母（如單日第 21 次更新為 `v1.7.2a`，後續為 `v1.7.2b`、`v1.7.2c` 等），字母單獨記數，並在紀錄中註明「已達單日 0.2.0 上限，改以字母遞增」。
4. **隔日重置與 Patch 推進**：
   - 隔日第一次更新時，自動移除英文字母，並以末位 Patch +1 起跳（例如前日最高為 `v1.7.2a`，次日第一次更新即為 `v1.7.3`），並重置享有當日 `0.2.0` 的增量額度與版本序號續接。
5. **重大更新標註**：
   - 凡涉及核心金流、架構變更、全新模組或資安法規之改動，需特別標註 `🔥【重大更新】`。
6. **時區標準 (UTC+8 臺灣標準時間)**：
   - 全平台版本更新日期、清單資料夾命名與版本資訊日誌，一律以 `UTC+8`（臺灣標準時間）為標準。
7. **全站前後端與內部清單版本同步原則 (Full-Stack Version Sync)**：
   - 每次版本更動時，版本號（如 `v1.5.5`）與更新日期（如 `2026.10.05`）必須 100% 同步於：
     - (1) 全域設定與專案檔：`src/data/versionData.ts`、`package.json`
     - (2) 平台內部清單與 ZIP 資料夾命名：`src/data/platformManual/` 各模組與 `IdeaX平台清單_v版本_日期.zip`
     - (3) 前端相應展示介面：全站頁尾 `Footer`、用戶個人儀表板、超管後台、`AboutUs` 關於我們、內部清單頂部標籤
     - (4) 後端相應介面：後端服務 `/api/health` 與 `/api/version` 介面
     - 杜絕任何一處前後端或手冊清單版本顯示不一致。
8. **文件儲存與導出格式規格 (Word & 文字檔標準，嚴禁 JSON 儲存)**：
   - 內部清單手冊、模組內容與 ZIP 打包導出，**嚴禁使用 JSON 格式儲存或傾倒原始碼**。
   - 一律採用排版工整之純文字檔（`.txt` / `.md`）與 Microsoft Word 相容文件（`.doc` / `.docx`），保證所有使用者與管理員點開即可在 Office Word、WPS 或記事本中清晰閱讀。
9. **自動謄寫義務**：
   - 每次代碼修改完成後，工程師必須主動將新版本號與日期更新於 `src/data/versionData.ts`，並在 `src/data/platformManual/versionHistory.ts` 內追加詳細更新細項。

## 🔒 權限安全原則
- **「平台內部清單」僅限超管/管理員席位（`currentUser.role === 'admin'`）可見**。
- 非管理員身分（提問者、專家、訪客）一律不顯示入口，組件端進行嚴格阻截返回 `null`。
